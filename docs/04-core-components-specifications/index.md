This chapter introduces the core components that constitute the foundation of MaaS Blender.
Each component defines a distinct responsibility in the simulation workflow, from demand generation to planning, execution, and evaluation.

## Component Overview

MaaS Blender is built on five core component types, each with clearly defined responsibilities and event-based interfaces:

1. **Scenario (Demand Generator)**: Generates travel demands that initiate user activities in the simulation. Multiple implementations support different demand patterns: stochastic flows, historical replay, and recurring commuter behavior.

2. **User Model**: Represents the decision-making and trip orchestration logic of individual users. Converts travel demands into executable tasks by coordinating route planning, service selection, and reservations.

3. **Route Planner**: Provides multi-modal journey planning capabilities. Converts travel intentions (origin, destination, departure time) into route candidates with multiple transportation modes and services.

4. **Mobility Service**: Represents transportation providers that can be integrated into the simulation platform. Each service manages its own resources and responds to reservation and departure requests through a standardized event contract.

5. **Evaluation**: Auxiliary components that observe simulation behavior in real time without influencing it. Captures information that cannot be fully reconstructed from event logs alone, enabling richer analysis.

## Event-Driven Architecture

All components interact through a unified event-based protocol:
- `DEMAND`: Travel requests generated by scenarios
- `RESERVE` / `RESERVED`: Reservation requests and confirmations
- `DEPART` / `DEPARTED`: Trip initiation events
- `ARRIVED`: Trip completion events

This architecture enables heterogeneous components to work together seamlessly, regardless of their internal implementation.
